# Сервис поиска специалистов по ремонту

Веб-приложение Django для просмотра специалистов по ремонту, подбора по специализации и ставке, просмотра заявок и статистики. Веб-слой работает с базой данных через Django ORM. Консольный интерфейс и JSON-хранилище сохранены.

## Реализованные возможности

- каталог специалистов, упорядоченный по ставке;
- подбор специалистов по специализации и максимальной ставке;
- карточка специалиста и обработка отсутствующей записи ответом 404;
- список заявок с карточками клиента, специалиста и услуги;
- фильтрация заявок по дате, клиенту, специалисту, услуге и статусу;
- сортировка заявок по дате, клиенту, специалисту или услуге;
- пагинация списка по пять записей с сохранением параметров фильтрации и сортировки;
- карточка заявки с контактами клиента, статусом и расчётом ориентировочной стоимости;
- статистика количества заявок по статусам и специалистам;
- Django ORM-модели клиента, специалиста, услуги и заявки с внешними ключами;
- перенос исходных данных SQLite ПР7 в базу Django с сохранением идентификаторов и связей;
- базовые шаблоны, именованные маршруты, статические CSS/JavaScript/SVG и Bootstrap 5.3;
- консольные операции и JSON-хранилище из предыдущих работ.

Веб-формы создания и редактирования данных не реализованы. Исходная база ПР7 в `data/repair_service.sqlite3` сохраняется для импорта; Django ORM работает с `db.sqlite3`.

## Маршруты

| URL | Страница |
| --- | --- |
| `/` | Главная |
| `/specialists/` | Каталог специалистов |
| `/specialists/search/` | Подбор по специализации и максимальной ставке |
| `/specialists/<specialist_id>/` | Карточка специалиста |
| `/requests/` | Список заявок с фильтрацией, сортировкой и пагинацией |
| `/requests/<request_id>/` | Карточка заявки |
| `/requests/statistics/` | Статистика заявок |
| `/admin/` | Административная зона Django |

Список заявок принимает GET-параметры `date`, `client`, `specialist`, `service`, `status`, `sort` и `page`.

## Модели и база данных

- `homepage.models.Client`: имя и телефон;
- `specialists.models.Specialist`: имя, специализация и ставка;
- `repair_requests.models.Service`: название, требуемая специализация и длительность;
- `repair_requests.models.RepairRequest`: дата, статус и внешние ключи на клиента, специалиста и услугу.

Модели и связи создаются миграциями Django. Для заявок используется `select_related()` при получении связанных данных; статистика строится ORM-агрегациями. Таблицы исходной базы ПР7 описаны в `sql/schema.sql`. Скрипт `db/import_sqlite_to_orm.py` читает `data/repair_service.sqlite3` и создаёт/обновляет ORM-записи в `db.sqlite3`, сохраняя ID и связи.

## Структура

- `repair_service/` — конфигурация Django и корневая маршрутизация;
- `homepage/` — главная страница и модель клиента;
- `specialists/` — каталог, поиск и модель специалиста;
- `repair_requests/` — страницы заявок, статистика и модель услуги/заявки;
- `templates/` — HTML-шаблоны страниц;
- `db/` — подключение к исходной базе, импорт JSON и перенос в ORM;
- `data/` — JSON-источники и база SQLite ПР7;
- `sql/` — схема и примеры запросов исходной базы;
- `models/`, `storage.py`, `main.py` — предметные классы, JSON-хранилище и консольный интерфейс;
- `manage.py` — команды Django.

## Установка и запуск

Из корня проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py shell -c "from db.import_sqlite_to_orm import import_sqlite_to_orm; import_sqlite_to_orm()"
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`. Команда переноса нужна для заполнения базы Django данными из уже существующей базы ПР7. Консольная версия запускается отдельно: `python main.py`.
